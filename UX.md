# Experiência da aluna

## Para quem estamos criando

A aluna pode nunca ter estudado para concurso.

Pode não conhecer nenhuma palavra da matéria.

Pode estudar quase sempre pelo celular.

Pode se distrair com facilidade.

Por isso, o curso deve mostrar o caminho sem esperar que ela descubra tudo sozinha.

## A pergunta mais importante

Em qualquer página, a aluna precisa saber:

- onde está;
- o que vai aprender;
- quanto tempo pode levar;
- o que fazer depois.

Se ela precisar pedir ajuda para encontrar a próxima aula, precisamos melhorar a página.

## A sensação que queremos criar

O curso deve parecer uma boa aula particular.

A aluna deve sentir que existe alguém dizendo:

> “Vem comigo. Primeiro vamos entender isto. Depois você tenta. Se não der certo, eu explico de outro jeito.”

Não queremos páginas frias.

Não queremos textos que pareçam instruções de um programa.

Não queremos impressionar com palavras difíceis.

Queremos ensinar.

## Página inicial

Em menos de 10 segundos, a página inicial precisa mostrar onde começar.

Ela deve ter:

1. uma mensagem curta de boas-vindas;
2. um botão grande **COMEÇAR A ESTUDAR**;
3. o módulo disponível;
4. as aulas que já podem ser abertas;
5. as disciplinas que ainda estão em preparação.

O botão principal sempre leva para **Como usar este curso**.

Não coloque duas escolhas com o mesmo destaque logo no começo.

## Menu do curso

O menu segue esta ordem:

```text
Disciplina
└── Módulo
    └── Aula 1 • Nome da aula
```

Regras:

- mostrar nomes que uma pessoa comum entende;
- numerar módulos e aulas;
- manter a mesma ordem em todas as páginas;
- não mostrar nomes de arquivos;
- não criar links para aulas que ainda não existem;
- escrever **Em preparação** quando o conteúdo ainda não estiver pronto;
- deixar no menu apenas o que ajuda a aluna a estudar.

## Topo de cada aula

Logo abaixo do título, toda aula deve mostrar um cartão com:

- disciplina;
- módulo;
- `Aula X de Y`;
- tempo estimado;
- objetivo explicado em uma frase simples.

Exemplo:

```text
Administração Geral
Módulo 1 • Fundamentos da Administração Pública
Aula 3 de 5

Tempo estimado: cerca de 90 minutos

Objetivo: entender a diferença entre a Administração Direta e a Indireta.
```

O cartão deve ter sempre a mesma aparência.

## Final de cada aula

Toda aula termina com:

```text
← Aula anterior
Próxima aula →
```

Os botões precisam funcionar no celular e no computador.

A primeira aula pode voltar para a página inicial.

Se ainda não existir uma próxima aula, diga isso com clareza.

A aluna nunca pode chegar ao fim e pensar: “E agora?”.

## Jeito de conversar

Escreva como uma professora paciente conversaria com uma amiga.

Use:

- frases curtas;
- parágrafos curtos;
- perguntas durante a explicação;
- exemplos que a aluna consegue imaginar;
- palavras comuns;
- orientações diretas.

Evite:

- tom de manual;
- tom de lei fora das citações necessárias;
- frases que parecem relatório;
- broncas;
- promessas de aprovação;
- palavras difíceis usadas para parecer importante.

Quando uma palavra da prova for difícil:

1. explique a ideia com palavras comuns;
2. dê um exemplo simples;
3. apresente o nome usado na prova;
4. continue a explicação sem complicar.

## Ritmo da aula

A aluna pode perder a concentração.

Por isso:

- não crie blocos enormes de texto;
- mude o ritmo com perguntas e exemplos;
- faça pausas em pontos importantes;
- use listas apenas quando ajudarem;
- não encha a página de caixas coloridas;
- termine cada parte mostrando a ideia principal.

Uma tela deve trazer uma ideia principal de cada vez sempre que isso for possível.

## Celular primeiro

Todas as páginas devem funcionar bem no celular.

Confira:

- se o texto tem margem confortável;
- se os botões são fáceis de tocar;
- se tabelas não obrigam a ler letras minúsculas;
- se o menu pode ser aberto com facilidade;
- se os parágrafos são curtos;
- se nenhuma informação depende apenas de cor;
- se links deixam claro para onde levam.

No computador, deixe apenas a árvore do curso à esquerda e a aula no centro.

No celular, mantenha somente o topo necessário para abrir o menu.

## Área de leitura

Remova o que disputar atenção com a aula.

Não mostrar:

- índice à direita;
- botão de editar;
- rodapé técnico do gerador do site;
- elementos decorativos sem função;
- informações do repositório.

A linha de texto pode ser ampla, mas não deve atravessar a tela inteira.

## Botões

O botão mais importante recebe mais destaque.

Exemplos:

- **COMEÇAR A ESTUDAR**;
- **Próxima aula →**.

O botão de voltar deve aparecer, mas pode ter menos destaque.

Os textos precisam ser fáceis de entender. Não use “Clique aqui”.

## Conteúdo disponível e conteúdo futuro

A aluna precisa saber o que pode estudar agora.

Use apenas estas mensagens:

- **Disponível:** pode abrir e estudar;
- **Em preparação:** ainda não está pronto;
- **Em revisão:** existe, mas ainda está sendo conferido;
- **Atualizado em:** seguido da data da última conferência.

Não apresente página vazia como aula.

Não prometa uma data que ainda não foi decidida.

## Antes de publicar uma mudança

Faça o caminho completo:

1. abra a página inicial;
2. encontre **COMEÇAR A ESTUDAR** sem procurar;
3. leia **Como usar este curso**;
4. avance pelas aulas;
5. volte uma aula;
6. abra uma aula do meio pelo menu;
7. confira o cartão do topo;
8. teste pelo celular;
9. confira todos os links;
10. execute `mkdocs build --strict`.

## Pergunta final

Antes de dizer que a mudança está pronta, pergunte:

> “Uma pessoa que nunca estudou para concurso conseguiria usar isso sem pedir ajuda?”

Se a resposta for “talvez”, reescreva.

- [ ] O botão principal leva ao primeiro passo certo.
- [ ] O menu mostra disciplina, módulo e aula.
- [ ] Cada aula mostra tempo e objetivo.
- [ ] Cada aula tem botões para continuar.
- [ ] As palavras difíceis foram explicadas.
- [ ] Os parágrafos são curtos.
- [ ] A página funciona no celular.
- [ ] Não existe índice à direita.
- [ ] Não há links quebrados.
- [ ] O site abre sem avisos de erro.
